# devlog-rotate — log.md のローテーションと修復

## 目的

`log.md` は追記専用で単調増加し、「追記だけして全体を見ない」ことで3種類の破損が起きる
（正本: `development-guidelines/guides/recording.md`「log.md の3規律」）。
このスキルは**月替わり・20,000字超・見出しの乱れ**を1コマンドで機械的に正す。

- ① 日付は `## YYYY-MM-DD` 見出しのみ・降順 → 検査し、`--blame` なら blame のコミット日で付け直す
- ② 月替わり or 20,000字超で `log/YYYY-MM.md` へ退避（同月2回目は `-2`）・過去ログ表・`../` 化・リンク検査
- ③ 1エントリ1〜2文 → 700字超を**警告だけ**（縮めるのは人／Claude の判断）

## 使うタイミング

1. **月初に docs/ を初めて触るとき**（前月分を退避）
2. `log.md` が 20,000 字を超えたとき（Stop フックや目視で気づいたら）
3. 見出しの順序・重複・行頭日付形式・`New`/`Add`/`Fix` ラベルが混ざっていると気づいたとき

## 手順

### 1. まず検査（書かない）

```bash
python .claude/skills/devlog-rotate/scripts/rotate_log.py --check docs/log.md
```

- exit 0 ＝ 対応不要。exit 2 ＝ 要対応（過去月あり／文字数超過／書式の問題）。出力の `⚠` 行を読む。
- 「日付でも過去ログでもない見出し」「解釈できない行」が出たら**スクリプトは触らない行**なので先に手で直す。

### 2. 対象ファイルがコミット済みか確認

スクリプトは**未コミットの変更があると書き換えを拒否**する（git が唯一のバックアップ）。
`git status --short docs/log.md` が空であることを確認。空でなければ先にコミット。

### 3. 実行

通常のローテーション（見出しの日付を信じる）:

```bash
python .claude/skills/devlog-rotate/scripts/rotate_log.py docs/log.md --actor claude/<このセッションのモデルID>
```

修復モード（見出しが信用できない＝1つの見出し下に別の日のエントリが積まれている）:

```bash
python .claude/skills/devlog-rotate/scripts/rotate_log.py docs/log.md --blame --actor claude/<モデルID>
```

- `--actor` を付けると、ローテーション自体の log 行を当日見出しの先頭に自動挿入する（**付けること**。
  log.md 自身の編集にも companion 行が要る）。
- `--today YYYY-MM-DD` で日付を固定できる（日付をまたいだ作業・検証用）。
- `--limit N` で文字数上限を変えられる（既定 20,000）。

### 4. 出力を確認して報告

- `リンク検査: 壊れ 0 件` と `INDEX 収載検査: 未収載 0` を確認（0 でなければ退避ファイルのリンクを手で直す）
- `書式統一: {...}` に `legacy` や `label:New` が出ていたら、何件をどう直したか報告する
- `③ 長すぎるエントリ` が出ていたら件数を報告（直すかはユーザー判断。本文へ移して要約に縮める）
- 規約②の「総括とログの乖離チェック」はここで相乗りする: 退避分に登場した「個別ログ＋総括の2層」型
  ドキュメントの総括が最新ログを反映しているか目視で突合する（スクリプトは INDEX 収載の有無までしか見ない）
- `git diff --stat` で log.md と `log/` の差分を見せ、コミット

## スクリプトの動作（安全設計）

- `--check` は一切書かない。書き換え時も**対象に未コミット変更があれば拒否**（`--force` で無視）
- 退避先が既にあれば上書きせず `log/YYYY-MM-2.md`, `-3` … を使う（規約どおり）
- 既存の「過去ログ」表の行は保持し、新しい行を足して月の降順に並べ直す
- 退避分のエントリだけ相対リンクを `](x)` → `](../x)` に書き換え（`http(s)://`・`../`・`/`・`#` 始まりは触らない）
- 当月分が上限を超えたときは**今日の分だけ残して**当月分も退避する
- 書き出し後に全ファイルの相対リンク解決と、`INDEX.md`（log.md と同じ階層＋1階層下）への収載を機械検査
- 依存は Python 3 標準ライブラリと `git` のみ。Windows の cp932 コンソールでも UTF-8 で出力する

## 既知の限界

- blame モードは「行が最後にコミットされた日」を使う。深夜 0 時またぎや、過去行の文言修正が
  あった行は実際の記録日とずれる（下記の実測では 197 行中ずれは見つからなかった）
- 行頭日付形式（`- YYYY-MM-DD path 内容`）の変換は実際に見た形だけに対応。アクターは `claude/unknown` になる
- 「総括とログの乖離チェック」は機械化していない（上記手順4で目視）

## 実測（2026-10-03）

知見リポジトリの log.md（227行・46,905字・見出しが `08-22, 08-21, 08-21, 08-13, 09-24, 10-01` と乱れ、
`08-13` の見出し下に 6 週分が積まれていた）を `--blame` で修復: 8月 104 件・9月 49 件を退避、
当月 44 件で約 1 万字に。元エントリと退避後エントリの集合差は変換した行頭日付形式 4 行だけ（無損失）。
壊れたリンク 0・INDEX 未収載 0。同じ入力への再実行は「対応不要」（冪等）。
