# 質問票: `pet-core::chat` の要求書（core-requirements.md）

各項目に「テスト作成係が採った解釈」と「テストがその解釈に依存しているか」を書いた。
依存「なし」の項目は、どちらに決まってもテストは変わらない（その入力をテストで使っていない）。

## Q1. §6 の検査は、140 字に切り詰めた後の文で行うのか

「判定は sanitize 後の文で行う」とあり、手順では `sanitize_line(s, BUBBLE_MAX_CHARS)` が切り詰めも兼ねる。
すると、141 字目以降にある URL は検査から漏れる（切り捨てられるので表示もされない）。問題は境界をまたぐ秘密で、
40 字の鍵が 130 字目から始まると、切り詰め後は 9 字＋`…` しか残らず 32 字未満になり、**鍵の先頭 9 字が吹き出しに出る**。

- 採った解釈: 書かれたとおり、切り詰め後の文で判定する（参照実装もそう書いた）
- 代案: 切り詰め前（`sanitize_line(s, usize::MAX)` 相当）で判定し、出すときだけ 140 字に切る。N3 の趣旨からはこちらが安全
- テストの依存: **なし**（境界をまたぐ入力は使っていない）。決まったらテストを 1 本足す

## Q2. §6 の「英数字」「英字」は ASCII に限るのか

`char::is_alphanumeric` は日本語（かな・漢字）でも true を返す。Unicode で数えると、区切りの無い 32 字以上の日本語の文が
「秘密らしい並び」になり、同じ節の「普通の日本語の文はそのまま」と矛盾する。

- 採った解釈: ASCII の英数字（`is_ascii_alphanumeric`）と ASCII の英字（`is_ascii_alphabetic`）。`sk-` の直前の判定も ASCII
- テストの依存: **あり**（`bubble_text_long_japanese_run_is_not_secret` は 40 字以上の区切りなしの日本語がそのまま出ることを確かめる。
  `bubble_text_hides_sk_prefix_words` の「日本語sk-abc」は直前が日本語なので隠す側）

## Q3. §6 の `sk-`・`www.` は大文字小文字を区別するのか

`SK-xxx`・`WWW.example.com` を隠すかが書かれていない。

- 採った解釈: 書かれた字面どおり（小文字だけ）。ただし安全側に倒すなら大文字小文字を無視する案もある
- テストの依存: **なし**（大文字の入力は使っていない）

## Q4. §5 の「空」は空文字だけか、空白だけの文字列も含むか

`"result": "   "` のとき、成功側は `Answer { text: "   " }` か `Failed { "答えが空でした" }` か。
失敗側（is_error）は `bubble_text("   ")` = `"（答えが空でした）"` か `"Claude Code がエラーを返しました"` か。

- 採った解釈: 「空」＝空文字（`""`）だけ。空白だけの答えは Answer になり、表示の時に §7 が `"（答えが空でした）"` にする
- テストの依存: **なし**（空白だけの result は使っていない）

## Q5. §5 で `is_error` が真偽値でない時（`"is_error": "true"` など）の扱い

- 採った解釈: 真偽値の `true` のときだけ失敗扱い。それ以外は「false か無い」と同じ
- テストの依存: **なし**

## Q6. §9 で `loggedIn: true` かつ `authMethod` が無い・文字列でない時

「それ以外の文字列の authMethod → その他の接続」は文字列の場合しか書いていない。

- 採った解釈: 「その他の接続」（参照実装）。「確かめられませんでした」も筋が通る
- テストの依存: **なし**

## Q7. §9 の `subscriptionType` が空文字の時

「英数字だけの時だけ使う」は空文字でも（空虚に）真になる。そのまま使うと `"サブスク（）"` になる。

- 採った解釈: 空文字は使わず `"サブスク"`
- テストの依存: **なし**（空文字は使っていない）

## Q8. §9 の `loggedIn` が真偽値でない時（`"loggedIn": "true"` など）

- 採った解釈: 「`loggedIn` が無い」と同じ扱いで `"確かめられませんでした"`。`null` も同じ
- テストの依存: **あり（null だけ）**（`auth_status_unreadable` は `"loggedIn": null` を「確かめられませんでした」とする。
  文字列の `"true"` は使っていない）

## Q9. §7 の「前後の空白・改行を落とす」と「4000 字で切る」の順番

箇条書きの順（落とす → 切る）に従うと、前後に空白がある 4000 字の本文は切られない。逆順だと切られる。

- 採った解釈: 箇条書きの順（先に落としてから数える）。「前後の空白」は `str::trim` の範囲（Unicode の空白）
- テストの依存: **あり**（`panel_text_trims_before_counting`）。全角空白は使っていない

## Q10. §6 の切り詰めと §7 の切り詰めは「…」の手前に残った空白をどうするか

`sanitize_line` も §7 も「先頭 N-1 字＋…」なので、N-1 字目が空白なら `"… "` ではなく `" …"` になる。

- 採った解釈: 書かれたとおり（空白を残す）。見た目の問題だけなのでテストでは扱わない
- テストの依存: **なし**

## Q11. §4 で `parent` に値が空の `ANTHROPIC_API_KEY=` があり、ApiKey の時

取り除いてから 1 つ足すので結果は「ちょうど 1 つ」で、要求に矛盾は無い。確認のみ。

- テストの依存: なし（`mixed_parent` に同名が 2 つ・小文字の 1 つを入れ、どれも消えて 1 つだけ足されることを確かめている）
