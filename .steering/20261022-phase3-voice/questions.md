# 質問票: `pet-core::voice`（テスト作成係 → 司令塔）

対象テスト: `crates/pet-core/tests/voice.rs`。根拠は `core-requirements.md` だけ。
「依存する」は、その解釈が外れるとテストが落ちる（＝要求書を直すか、テストを直す必要がある）という意味。
「依存しない」は、曖昧さを避けた入力だけを使っているので、どちらの解釈でもテストは通る。

## speech_for_answer

### Q1. パス・コード・秘密らしい文字列を `bubble_text` が隠す条件

- 要求書: 「URL・パス・コード・秘密らしい文字列があれば `BUBBLE_HIDDEN`」とあるだけで、検出の細部は `chat` 側
- 採った解釈: 手順 3 は `bubble_text` の結果に従う。URL だけは `ANSWER_IN_PANEL` を決め打ちで期待する。パス・コード・秘密らしい入力は、要求書の手順を書き写した参照関数（`expected_speech`）と突き合わせる
- 依存: URL の決め打ちは依存する（要求書に明記）。それ以外は `bubble_text` の挙動に追従するので依存しない

### Q2. 末尾の `…` を落とす条件

- 要求書: 手順 4「`b` の末尾の `…`（1 字）を落とし」。140 字超で付いた `…` に限るとは書いていない
- 採った解釈: 無条件に末尾の 1 字を落とす。元の答えが「考え中…」でも「考え中」になる
- 依存: する（`answer_speech_trailing_ellipsis_is_dropped_even_when_not_truncated`）

### Q3. `…` が連続して終わる文

- 要求書: 落とすのは 1 字。「……」で終わる文が `…` 1 字分だけ残るかは明記なし（残ると読める）
- 採った解釈: テストに使わない
- 依存: しない

### Q4. 答えがちょうど 140 字の場合の字数

- 要求書: 140 字を超えたら 139 字＋`…`。ちょうど 140 字は切られない
- 採った解釈: 140 字ちょうどは 140 字のまま話す。141 字以上は 139 字
- 依存: する（`answer_speech_over_140_chars_drops_the_ellipsis`）

## SpeechQueue

### Q5. 冷却の起点

- 要求書: 「同じ文言を最後に話し始めてから」、`next` で「最後に話し始めた時刻を `now` にする」
- 採った解釈: 起点は `next` を呼んだ時刻（`push` した時刻ではない）
- 依存: する（`queue_cooldown_is_measured_from_when_speech_started_not_from_push`。0 に積み 1000 に話し始めると、15000 に積んだものは冷却中）

### Q6. 「最後に話し始めた時刻」の初期値

- 要求書: 状態に「固定文言ごとに最後に話し始めた時刻」とあるが、未記録のときの扱いは書いていない
- 採った解釈: 未記録は冷却なし。`now = 0` で最初の固定文言を積んでも受ける（初期値 0 と取り違えない）
- 依存: する（`queue_first_phrase_is_accepted_at_time_zero`）

### Q7. 冷却のキー（空白の扱い）

- 要求書: `push` は前後の空白を落としてから見る。冷却の「同じ文言」を、空白を落とした文字列で比べるかは明記なし
- 採った解釈: テストでは、冷却の照合に空白あり・なしの違う綴りを使わない（`queue_texts_are_trimmed` は冷却とは別に `next` の戻り値だけ見る）
- 依存: しない

### Q8. 冷却中の固定文言が、待っている固定文言を押しのけるか

- 要求書: 冷却中は「捨てる」。待っている固定文言をどうするかは書いていない
- 採った解釈: 捨てるだけで、待っている固定文言はそのまま残る
- 依存: する（`queue_cooled_down_phrase_does_not_replace_a_waiting_phrase`）

### Q9. 押しのけられた固定文言の冷却

- 要求書: 冷却に使うのは「話し始めた時刻」
- 採った解釈: 話し始める前に答えや別の固定文言に押しのけられた固定文言は冷却を始めない。直後に積み直せば受ける
- 依存: する（`queue_answer_pushes_out_a_waiting_phrase`・`queue_later_phrase_replaces_a_waiting_phrase`）

### Q10. 答えを話し始めたとき、同じ文面の固定文言の冷却が始まるか

- 要求書: `next` が時刻を更新するのは「`Phrase` だったら」だけ
- 採った解釈: `Answer` は冷却を始めない。`Answer("できたよ")` を話した直後に `Phrase("できたよ")` を積んでも受ける
- 依存: する（`queue_speaking_an_answer_does_not_start_a_phrase_cooldown`）

### Q11. 話し中に捨てられた固定文言が `finished` の後に出てくるか

- 要求書: 「話し中なら捨てる」
- 採った解釈: 出てこない（溜めない）
- 依存: する（`queue_phrase_pushed_while_speaking_is_dropped`）

### Q12. 空白だけの `Utterance` と待っている 1 件

- 要求書: 「空なら何もしない」
- 採った解釈: 待っている 1 件も話し中の状態も変わらない（空白だけの `Answer` は待っている `Phrase` を押しのけない）
- 依存: する（`queue_blank_*`）。空白の定義は `str::trim` が落とす範囲のうち ASCII の空白・タブ・改行だけを使っている

### Q13. `now_ms` が巻き戻る場合

- 要求書: 「時刻は引数のミリ秒（単調増加）」
- 採った解釈: テストは常に単調に増える時刻だけを渡す（冷却の差の引き算が下回る入力を作らない）
- 依存: しない

### Q14. `finished(now)` の `now` の使い道

- 要求書: 何も使うと書いていない
- 採った解釈: 結果に影響しない。テストは意味のある時刻を渡すが、その値に結果を依存させない
- 依存: しない

## rms と Endpointer

### Q15. `rms` の精度としきい値ちょうどの比較

- 要求書: 「f32 にして二乗平均の平方根」。累積を f32 でやるか f64 でやるかは実装の自由
- 採った解釈: 二乗和が f32 でも厳密に表せる振幅（300・600・1200 と、その 1/3 の背景音 100・200・400 など）だけを「ちょうど」の境界に使う（`rms >= しきい値` の `=` 側）。それ以外の `rms` の値は相対 1e-4 の誤差を許す
- 依存: する（`endpointer_threshold_is_max_of_floor_and_three_times_the_quiet_level` は 300・600・1200 ちょうどで話していると判定されることを要求する）

### Q16. 「測る間」の境界をまたぐフレーム

- 要求書: 「そのフレームを受け終えた時点の `elapsed_ms` が `CALIBRATION_MS` 以下のフレームは測定にだけ使う」。受け終えた時点が 300 を超えるフレーム（例: 280ms から 310ms）は、全体が判定に使われる
- 採った解釈: 文字どおり。境界をまたぐフレームの前半を測定に使う、のような分割はしない
- 依存: しない（フレームの終わりがちょうど 300ms になる入力だけ使う）。ちょうど 300ms で終わるフレームは測る間に入ることは `endpointer_calibration_window_includes_the_frame_ending_at_300ms` で要求する（要求書の「以下」）

### Q17. 話している長さ・黙っている長さの ms への換算

- 要求書: 「サンプル数から ms」。フレームごとに切り捨てるか、合計してから換算するかは書いていない
- 採った解釈: テストは 16 の倍数のサンプル数（160・480）のフレームだけで長さを数えるので、丸め方に依存しない
- 依存: しない。ただし `elapsed_ms` だけは「合計サンプル × 1000 / 16000 の切り捨て」と要求書にあるので、端数が出る入力（15 + 1 + 17 サンプル）で確認している（依存する: `endpointer_elapsed_ms_counts_samples_and_floors_the_total`）

### Q18. 空のフレームと静かさの測定

- 要求書: 「空のフレームは経過時間を進めず、判定も変えない」
- 採った解釈: 空のフレームは静かさの測定（`rms = 0.0` の 1 サンプル）にも混ぜない
- 依存: する（`endpointer_empty_frame_is_not_counted_as_a_quiet_sample`。混ぜると背景音 400 のしきい値が 300 に下がり、1000 の音を話していると取り違える）

### Q19. `Ended` の後の空のフレーム

- 要求書: 戻り値の 1 番目が「既に `Ended(r)` なら同じ `Ended(r)`」、別の項に「空のフレームは戻り値は今の状態」
- 採った解釈: どちらも同じ結果になる。`Ended` の後に空のフレームを押しても `Ended(r)`
- 依存: する（`endpointer_ended_state_never_changes`）

### Q20. 2 の判定（Done）と 4 の判定（MaxLength）が同じフレームで成り立つとき

- 要求書: 「この順に見る」と明記
- 採った解釈: Done が勝つ
- 依存: する（`endpointer_done_wins_over_max_length_when_both_hold_on_the_same_frame`）

### Q21. 話し始める前の沈黙の数え方

- 要求書: 「`heard_speech` が true になる前の黙りも数えてよい」（数えるかは実装の自由）
- 採った解釈: 話している最中は 0 に戻るので、`heard_speech` が true になった時点の値は結果に出ない。テストは、どちらの実装でも同じ結果になる入力だけにしている
- 依存: しない

### Q22. `Endpointer` の `Default`

- 要求書: `new()` だけ。`derive(Debug)` のみで `Default` は無い
- 採った解釈: `Endpointer::default()` はテストしない
- 依存: しない

## transcript_text

### Q23. `key` から除く記号の範囲

- 要求書: 空白（Unicode の空白）と、列挙された記号（`。、．，.,!！?？・…「」『』（）()`）
- 採った解釈: 列挙された記号だけを除く。他の記号（`〜`・`ー`・`-` など）は除かない。テストは列挙内の記号だけを使う
- 依存: しない

### Q24. `sanitize_line` が全角空白（U+3000）を畳むか

- 要求書: 「空白の並びを半角 1 つに」。全角空白が空白に入るかは `hook` 側
- 採った解釈: 返り値に全角空白が含まれる入力の期待値は作らない。全角空白は `key` の側（幻聴の判定・空判定）でだけ使う
- 依存: しない

### Q25. 幻聴は完全一致だけを捨てる

- 要求書: 「句読点・空白を除いた形で完全一致したら捨てる」
- 採った解釈: 前後に別の語がある文（「こんにちは。ご視聴ありがとうございました」「ご視聴ありがとうございましたか」）は捨てずに、整形した文をそのまま返す
- 依存: する（`transcript_only_exact_hallucination_match_is_dropped`）

### Q26. 2000 字の数え方

- 要求書: 「`chat::input_text` で 2000 字超なら `None`」
- 採った解釈: 前後の空白を落とした後の `char` 数。2000 字は送る、2001 字は `None`
- 依存: する（`transcript_2000_chars_is_sent_and_2001_is_not`）

## wav_bytes と parse_wav

### Q27. `data` チャンクが奇数長で、後ろに詰め物が無いとき

- 要求書: 詰め物は「中身の後に 1 バイト」と書くが、`data` を見つけたらそこで読むのをやめる
- 採った解釈: `data` の後の詰め物は要らない。長さ 3 の `data` が末尾にあっても `Some`（`data_len` は 3）
- 依存: する（`parse_wav_accepts_an_odd_length_data_chunk_without_padding`）

### Q28. `data_len` は宣言した長さ

- 要求書: `Some(WavInfo { ..., data_len })`
- 採った解釈: 宣言された長さ。`data` の後ろに余りがあっても、余りは足さない。また `data` の後ろが壊れたチャンクでも読まない
- 依存: する（`parse_wav_reports_the_declared_data_len_and_ignores_trailing_bytes`）

### Q29. `RIFF` の次の 4 バイト（サイズ）

- 要求書: 「4 バイト何でもよい」
- 採った解釈: 0 でも `u32::MAX` でも検査しない
- 依存: する（`parse_wav_ignores_the_riff_size_field`）

### Q30. `fmt ` が 16 バイトより長いとき・奇数長のとき

- 要求書: 「長さ 16 以上」。奇数長は詰め物のルールに従う
- 採った解釈: 17・18・40 バイトの `fmt ` も読める。16 未満（0・2・14・15）は `None`
- 依存: する（`parse_wav_checks_the_fmt_chunk_length`）

### Q31. `fmt ` の前の未知チャンク

- 依存: する（`parse_wav_skips_unknown_chunks_before_fmt_and_between`）

### Q32. `fmt ` の本体が残りに収まらないとき

- 要求書: 未知チャンクの場合だけ「収まらなければ `None`」と書いてある。`fmt ` 自体が欠ける場合の扱いは書いていない

### Q33. `fmt ` が 2 回ある・`data` が 2 回ある

- 要求書: 書いていない（`data` は最初に見つけたところで読むのをやめる）

### Q34. `parse_wav` が先頭 12 バイトに満たない入力で panic しない
