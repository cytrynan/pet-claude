## 止まった点・直した点

0. **W10 で DisplaySwitch が効かなかった（既知の罠の踏み直し）**: Git Bash から `DisplaySwitch.exe /internal` を呼ぶと、MSYS が `/internal` をパスと見なして書き換え、DisplaySwitch はエラーも出さずに何もしなかった（`evidence/w10/steps.txt` の最初の項）。PowerShell から呼び直して成功。この罠は `dev/windows-powershell.md` に既にあり、`/` で始まる引数を Git Bash で渡す前に引けば避けられた

1. **掴んだ位置がずれた**: 1 回目のドラッグで、窓が指の下から 70px ほどずれた。`GetCursorPos` は「処理した時点」の位置を返すので、速く動かすとずれる。`GetMessagePos`（メッセージが発生した時点）に替えて解消した。ドラッグ中の座標を `PET_TRACE=1` でログに出せるようにした
2. **前面の判定が 1 回だけ想定と違った（原因未確定）**: 1 回目の W5 で、透明な角 (2675,1555) をクリックした後の前面が Chrome になった。このとき `WindowFromPoint` は背後をメモ帳（Edit）と返していたので、「背後の窓が反応した」では説明できない。2 回目以降（その場の 15 回、08:21 の 9 回）は再現しなかった。検証ツールの `SetForegroundWindow` が前面ロックで効かなかった可能性はあるが、確かめていない。08:21 の測り直しでは、点ごとに「背後の窓・クリック前後の前面・ペットの記録」を 1 行ずつ残した
3. **ドラッグが 1 回だけ届かなかった（原因未確定）**: 08:20 に `winctl drag` を送ったが、ペットのログにボタンの記録が無く窓も動かなかった。直後の再送は届いた。画面はロックされておらず、入力のアイドルは 3.6 秒だった（K の入力が重なった可能性があるが、確かめていない）
4. **古い exe で測りかけた**: ゲートは clippy とテストだけで実行ファイルを作り直さないので、初期位置の修正が反映されていない exe で W3 を測っていた。`cargo build -p pet-app --all-targets` を実機確認の前に走らせる、と CLAUDE.md と architecture.md に書いた
5. **初期位置が右端に付いていた**: 足元（下端中央）を作業領域の右端から 24px の位置に置いていたため、窓の右半分がはみ出してクランプされていた。窓の幅の半分を足して、右端・下端が 24px 内側に来るように直した
6. **最初のテストで 3 件失敗した。3 件ともテスト側の期待値の誤り**（実装は変えていない）:
   - `monitor_for_rect_prefers_largest_overlap`: 窓 (100,-100) 100×130 は、ノートと 100×30=3,000、ウルトラワイドと 100×100=10,000 重なる。ウルトラワイドが正しいのに、テストはノートを期待していた → 窓を (100,-20) にして、ノート 100×110=11,000 対 100×20=2,000 で「ノート」を確かめる形に直した
   - `monitor_for_rect_falls_back_to_nearest_when_offscreen`: (5000,2000) の窓の中心 (5050,2050) からの距離の二乗は、当時の想定値でノート 2,891²+701²=8,849,282、ウルトラワイド 1,994²+2,051²=8,182,637 で、ウルトラワイドのほうが近い。テストはノートを期待していた → 真下の (1000,3000) に直した
   - `corners_are_fully_transparent_and_body_is_opaque`: 体の画素として選んだ (96,150) が、わざと開けた「穴」（x 86〜105・y 142〜157）の中だった → (96,100) に直した
